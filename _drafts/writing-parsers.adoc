== Simple tokenizer

Since we are only naive here and not crazy, so we don't even bother with
{regex}[regular expressions] and plug some conditionals and a loop together:

[source,rust]
----
const STMNT: &str = "SELECT * FROM spotify;";

fn main() {
    let mut start: isize = -1;
    let mut stop: isize = -1;

    for (i, c) in STMNT.chars().enumerate() {
        match c {
            'A'..='Z' | 'a'..='z' => { // <.>
                if -1 == start {
                    start = i as isize;
                }

                stop = i as isize + 1;
            },
            ' ' | ';' => { // <.>
                if stop > start {
                    println!("Token `{:?}` at {}-{}",
                        &STMNT[start as usize..stop as usize], start, stop);

                    start = -1;
                    stop = -1;
                }

                if ';' == c { // <.>
                    println!("End-of-Stmnt at {}", i);
                }
            },
            '*' => { // <.>
                println!("Wildcard `*` at {}", i);
            },
            _ => panic!("Huh?"),
        }
    }
}
----
<.> Still naive, we just handle different characters here for our token handling
<.> Theses two characters have a special meaning for end of token resp. end or statement
<.> Either way we have to duplicate stuff without extraction into functions
<.> Let us handle wildcards differently; could probably also be just allowed as token character

== Tokenizer with FSM

I guess you've read this far just to see another {fsm}[FSM] and hell I don't
want to disappoint anyone here.
So let us solve this again, this this time with a bit of abstraction and
FSM-flavor and hopefully make my former university prof happy:

[source,rust]
----
use std::fmt;

const STMNT: &str = "SELECT * FROM spotify;";

#[derive(Debug)] // <.>
enum State {
    START,
    SCAN,
    TOKEN(usize, usize),
    WILDCARD(usize),
    BLANK(usize),
    #[allow(non_camel_case_types)]
    END_OF_STMNT(usize),
    END,
}

impl fmt::Display for State { // <.>
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        match self {
            State::START => write!(f, "START"),
            State::SCAN => write!(f, "SCAN"),
            State::TOKEN(start, stop) => write!(f, "TOKEN({}, {})", start, stop),
            State::WILDCARD(pos) => write!(f, "WILDCARD({})", pos),
            State::BLANK(pos) => write!(f, "BLANK({})", pos),
            State::END_OF_STMNT(pos) => write!(f, "END_OF_STMNT({})", pos),
            State::END => write!(f, "END"),
        }

    }
}

fn main() {
    let mut states: Vec<State> = vec![State::START]; // <.>

    let mut iter = STMNT.chars().enumerate();
    let (mut i, mut c) = iter.next().unwrap_or((usize::MAX, char::MAX));

    'parser: loop { // <.>
        match states.last().unwrap_or(&State::START) {
            State::START | State::SCAN => { // <.>
                match c {
                    'A'..='Z' | 'a'..='z' => {
                        states.push(State::TOKEN(i, i + 1));
                    }
                    ' ' => { // <.>
                        states.push(State::BLANK(i));
                    }
                    ';' => {
                        states.push(State::END_OF_STMNT(i));
                    }
                    '*' => {
                        states.push(State::WILDCARD(i));
                    }
                    _ => panic!("Unexpected char `{:?}`", c),
                }
            },
            State::TOKEN(start, _) => { // <.>
                match c {
                    'A'..='Z' | 'a'..='z' => {
                        let newstate = State::TOKEN(*start, i + 1);
                        states.pop(); // <.>
                        states.push(newstate);
                        (i, c) = iter.next().unwrap_or((usize::MAX, char::MAX)); // <.>
                    }
                    _ => states.push(State::SCAN),
                }
            },
            State::WILDCARD(_) => { // <.>
                states.push(State::SCAN);
                (i, c) = iter.next().unwrap_or((usize::MAX, char::MAX));
            },
            State::BLANK(_) => {
                states.push(State::SCAN);
                (i, c) = iter.next().unwrap_or((usize::MAX, char::MAX));
            },
            State::END_OF_STMNT(_) => {
                states.push(State::END);
            },
            State::END => {
                break 'parser; // <.>
            }
        }
    }

    #[cfg(feature = "debug")] // <.>
    for state in states.iter() {
        println!("{}", state);
    }

    for state in states.iter() { // <.>
        match state {
            State::TOKEN(start, stop) => println!("Token `{}` at {}-{}",
                &STMNT[*start..*stop], start, stop),
            State::WILDCARD(pos) => println!("Wildcard `*`at {}", pos),
            State::END_OF_STMNT(pos) => println!("End-of-Stmnt at {}", pos),
            _ => {},
        }
    }
}
----
<.> We start with the definition of our parsing states and use enum variants
<.> Deriving from {debug}[Debug] is nice, but let us also roll our own formatter
<.> We keep our states neatly collected in a vec, so we can do some post-processing later
<.> Technically not required here, but adding labels to loops make it a bit easier to follow
<.> Utilizing the FSM idea basically means we  step through the various states and have some checks,
if something is reasonable within its boundaries
<.> As before, the blank is some special case and we handle it accordingly
<.> The token state is something special, because it also keeps tracks of the start and stop position
<.> Handling a vector of {option}[options] is sometimes a pain to modify, so we just pop/push to basically
compact the many states this creates
<.> Iterator are also strictly safe-guarded, so we iterate here manually whenever we have to and
avoid peeking or stepping back
<.> The other states are a bit of repetitive, I left them in to make it easier to follow though
<.> Here is the break with the label, this is easier to follow, right?
<.> Another nifty feature is the {features}[feature] handling of Cargo, this allows us to see the
state list when enabled
<.> Any finally just the same output from the example before. *Noteworthy here it is decoupled from
the actual parsing.*

== Parser combinator

When I started spotql I did a quick check how one would write idiomatic parsers
with Rust and I quickly discovered the create {nom}[nom] - a parser combinators
library.
It took me quite a while until it made click and the migration from version 6
to version 8, which basically deprecated every macro in favor of functions,
didn't make it easier either.

{parsercombinator}[Parser combinators] or in general combinatory parsing works
slightly different, than how we did that in the two examples above.
Here we created our parsers as some kind a function, which accepts an input
string and after some processing returns some kind of structure as result.
The first parser didn't exactly do that, but technically the second did with
its states vector - a preliminary form of {ast}[AST].

Parser combinators, on the other hand, accept one or more parsers as an input
and generally return a new parser as its output.

of our well known statement how this actually works - again we rely only on
